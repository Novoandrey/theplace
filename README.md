# theplace

ИИ- и автоматизационный слой поверх инфраструктуры кофейни **The Place** (POS —
**Quick Resto**). Монорепо: каждый бот живёт в своей папке `bot_<имя>/`.

## Структура

```
theplace/
├── constitution.md            # принципы уровня проекта (правят все решения)
├── shared/                    # (далее) общий код между ботами
├── bot_pickup/                # Pilot 2 — бот самовывоза
│   ├── spec.md                #   ЧТО и ЗАЧЕМ
│   ├── research.md            #   ресёрч, референсы, пины версий
│   ├── data/
│   │   └── menu.json          #   реальное меню The Place (источник для v0)
│   └── (далее) plan.md, tasks.md, handlers/, services/, ...
└── (далее) bot_invoice/       # Pilot 1 — анализатор накладных
```

Планировочные доки бота (`spec.md`, `research.md`, `plan.md`, `tasks.md`) лежат в корне его
папки рядом с кодом. Если у бота появится несколько отдельных фич — заводим внутри `specs/<NNN>/`.

## Рабочий процесс (spec-driven)

`Constitution → Specify → Clarify → Plan → Tasks → Analyze → Implement`.
Каждая фича начинается со `spec.md` (ЧТО/ЗАЧЕМ), затем `plan.md` (КАК), затем `tasks.md`
(по user stories с чекпойнтами). Tech-детали — только в plan, не в spec.

## Текущий статус

- **bot_pickup:** есть `spec.md`, `research.md`, `plan.md`, `tasks.md`. Дальше — Implement (по одной
  задаче, начиная с T001).

## Принципы (кратко, полностью — в `constitution.md`)

- Mock-first, потом интеграция.
- Не дублируем штатный клиентский ТГ-бот Quick Resto.
- Нейтральный тон голоса.
- Клиентские сценарии не зависят от in-café интернета (внешний хостинг).
- Фискализация — явный слой, не допущение.
- Секреты — в окружении, не в гит.

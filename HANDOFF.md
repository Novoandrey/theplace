## 1. Проект
ИИ-/автоматизационный слой **поверх** POS кофейни The Place (POS — **Quick Resto**, точно). Не
заменяем учётную систему — добавляем сверху то, чего в ней нет. Стейкхолдеры: Aleksandr, Nikita.
Коммерческая рамка — бесплатная неделя discovery, потом обсуждение цены.

Два пилота:
- **bot_invoice** (Pilot 1) — приходные накладные. Распознавание (фото/PDF → vision → `*_extracted.json`)
  живёт в Claude-чате; заливка в QR через **открытое API** реализована и закрыта (путь A): трёхшаговая
  схема create (шапка → позиции → пересчёт), УПД 5699 (Калинин) залита и проведена на живой базе. Сейчас
  в работе — **постинг-бот** (`bot_invoice/server`), выносит заливку в Telegram.
- **bot_pickup** (Pilot 2) — бот приёма заказов на самовывоз. v0-core собран; в активной работе.

## 5. Ключевые решения и факты (чтобы не переоткрывать)
**Quick Resto API — ответ поддержки получен (2026-06-02):** два API.
- *Открытое* (бесплатно, любой тариф) — бэк-офис, GET/POST/DELETE, Basic Auth; логин/пароль в
  Предприятие → Настройки; docs https://quickresto.ru/api/ . Им **читаем меню**
  (`warehouse.nomenclature.dish`).
- *Закрытое* (**платно**) — отправка заказов на кассовый планшет → оттуда штатная печать на кухню и
  фискализация. **Решение Андрея: идём через закрытое платное API как основной путь доставки заказа.
  Звонок для подключения запрошен.**

**Quick Resto — приходные (путь A, подтверждено на живой базе, 2026-06-09):** `IncomingInvoice` в
`moduleName=warehouse.documents.incoming`; позиции — `warehouse.documents.items.incoming` (className
`InvoiceItem`); продукт — `…nomenclature.singleproduct.SingleProduct`; склад id=1 обязателен на create.
Создание — **3 шага** (create-шапка → add-item × N → update-`recalc`/пересчёт себестоимости); один POST
всей накладной даёт 500. Ставки НДС (%→id словаря vat): `{0:1, 5:4, 10:2, 22:3}`. Классы поставщика:
`organization` (Organization) / `businessman` (Businessman), ИП → businessman. Ведущая цена —
`priceWithVat` (из накладной); проверка дубля — по `documentNumber` через `/api/list` до создания.

**Касса/фискализация:** на кассе и на кухне стоит **АТОЛ** (ККТ, фото есть). Драйвер `libfptr10`
(Python, Linux/Win/mac, JSON-API, нефискальные документы) — запасной путь печати/фискализации. Рядом
с кассой — банковский пин-пад (карты), это отдельный торговый эквайринг.

**Печать на кухню (MVP):** путь **C** — отдельный дешёвый ESC/POS-принтер через локальный агент
(решение от 2026-06-02; v0-print). Закрытое API QR (исходящий вызов бота, штатная печать +
фискализация, агент не нужен) — целевой апгрейд (v1.1); libfptr10 на АТОЛ — нишевый запас. Всегда есть
дубль заказа в Telegram-чат кухни.

**Оплата (позже, v1.1):** банк кофейни — **Точка**. СБП через Точка.API (динамический QR, payload-ссылка
обходит ограничение Telegram desktop, вебхук `incomingSbpPayment`, комиссия ~0.4%). Фискализация
онлайн-оплат — через закрытое API QR или libfptr10; **оговорка 54-ФЗ**: ККТ должна быть
зарегистрирована под «расчёты в Интернете» — уточнить у бухгалтера.

**Меню:** `bot_pickup/data/menu.json`, 51 позиция, 10 категорий, расшифровано с фото. Фильтр —
**стаканом** (320 ₽; цену за стакан подтвердить). Объёмы напитков — отдельными позициями; альт. молоко
(+100) и сироп (+20) — опции; кухонные «Можем добавить» — отдельная категория.

**Выдача:** клиент даёт **имя один раз** в начале; **офис/адрес не нужны** (только самовывоз); на кассе
называет **короткий номер заказа** (FR-7), чтобы не забрать чужой.

**Стоп-лист:** при оформлении доступность перепроверяется; если позиция ушла в стоп — заказ **не
создаётся** (FR-16). Отмена части заказа + рефанд — later, завязано на оплату (FR-17).

**Стек (plan.md):** Python + aiogram 3.x (inline + FSM), Redis (FSM/корзина), Postgres + SQLAlchemy
async + Alembic, httpx, pydantic-settings, Docker Compose на VPS в РФ. Ключ — адаптеры `MenuSource`
и `OrderSink` (QuickRestoTerminal основной / TelegramStaffChat всегда / EscPosPrinter запас).

**Хостинг:** VPS в РФ (152-ФЗ — храним имя клиента), ~2 vCPU/4 ГБ, ~500–900 ₽/мес. **Не куплен.**
